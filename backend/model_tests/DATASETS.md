# Local Testing and Model Comparison Datasets

Inference can run with the existing pretrained weights; no training is required first. From
`backend`, run `python -m model_tests.run_depth` for single-image or directory prediction, metric
distance fusion, annotated images, and JSONL export. The script does not read ground-truth
annotations or calculate mAP, depth error, or formal video FPS. The static prediction entry point
uses `samples/bus.jpg` as its example image. Continuous video uses the replay files listed
separately below; this image script does not read them directly.

## Continuous Street Video for Local Integration

The current MVP focuses on obstacles and pedestrians near a walker. Prefer continuous street scenes
with a moving camera near eye level, occlusions, and pedestrians crossing paths. MOT17's moving
camera pedestrian-street sequences are suitable for replay integration, but do not represent a
complete pedestrian-navigation scenario.

The version-controlled assets comprise two official raw previews, two H.264 replay copies, and
the [SOURCES.json](datasets/street-video/SOURCES.json) manifest. Full datasets, annotation
packages, extracted frames, and run reports are managed separately and are not included in these
four videos. Prepare any additional data from its official source.

| Dataset and Official Source | Viewpoint, Data, and Suitable Stage | Acquisition and Repository Scope |
| --- | --- | --- |
| [MOT17](https://motchallenge.net/data/MOT17/) | Multi-object pedestrian tracking; sequence 07 is a daytime moving-camera pedestrian street, and 10 is a nighttime moving street scene. Training sequences include boxes, track IDs, and visibility annotations; no metric-depth or risk ground truth is provided. | The repository maintains four videos; the original JPG frame set (about 5.5 GB) and annotation package (about 10.1 MB) must be prepared separately. |
| [VeRLab EPIC2016](https://www.verlab.dcc.ufmg.br/semantic-hyperlapse/epic2016-dataset/) | Continuous first-person walking video from a head-mounted GoPro. Walking_25p is 1080p/30 FPS, about 6 min 06 s, and 915,677,261 bytes as a single file. It includes semantic detection results that can add replay scenes, but not metric-depth or risk ground truth. | Download the official single file; it is not included in repository assets. The data license is CC BY-NC 4.0. |
| [JAAD](https://data.nvision2.eecs.yorku.ca/JAAD_dataset/) | Urban roads from a vehicle viewpoint: 346 videos, 5–10 s at 30 FPS, with pedestrian boxes and crossing-behavior annotations; useful for adding crossing scenarios. | The official MP4 package is about 3.1 GB and must be downloaded separately. The website states that videos and annotations use the MIT license. |
| [JRDB](https://jrdb.erc.monash.edu/dataset/) | Robot viewpoint near human height, with RGB, LiDAR, and 2D/3D pedestrian annotations; suitable for checking distance and tracking with calibration. Panoramic-to-perspective camera correspondence requires separate adaptation. | The official legacy download requires login. Images, point clouds, calibration, and timestamp correspondences must be prepared separately and are not included in the repository. |

EPIC2016 refers to VeRLab's first-person video dataset, not EPIC-KITCHENS. Its Walking ratio is the
semantic-information proportion defined by the paper, not the proportion of obstacles. The
[package README](https://www.verlab.dcc.ufmg.br/hyperlapse/downloads/epic2016/README.md) states
that boxes in the MAT files were generated by a semantic detector; they must not be described as
manually verified pedestrian-tracking ground truth. Download the
[Walking_25p source video](https://www.verlab.dcc.ufmg.br/hyperlapse/downloads/epic2016/Source_Videos/Walking_25p.mp4)
directly without downloading the full 10 GB package. Its duration exceeds the current 55-second
inference session; the system does not silently segment it, resume it, or extend the session. See
the [official JRDB legacy download page](https://jrdb.erc.monash.edu/old) for its download format.

See [SOURCES.json](datasets/street-video/SOURCES.json) for video sources and license boundaries;
the project does not relicense the original videos. The sample scope includes only the four test
videos listed below and their source information, not full datasets, annotation ZIPs, extracted
frames, or local frame-by-frame run reports.

### MOT17 Replay Assets

The four videos are in `backend/model_tests/datasets/street-video/mot17/` and total 68,146,915
bytes. The table describes the MP4 file properties; see the annotation notes for the dimensions
of the original JPG frame sets.

| Sequence and Official Raw Preview | Split/Scene | MP4 Dimensions/FPS/Frames/Duration | Browser-Ready File |
| --- | --- | --- | --- |
| [MOT17-07-FRCNN-raw.mp4](datasets/street-video/mot17/MOT17-07-FRCNN-raw.mp4) | test; daytime moving camera, eye-level pedestrian street | 960×540 / 30 / 500 / 16.666667 s | [MOT17-07-FRCNN-browser-h264.mp4](datasets/street-video/mot17/MOT17-07-FRCNN-browser-h264.mp4) |
| [MOT17-10-FRCNN-raw.mp4](datasets/street-video/mot17/MOT17-10-FRCNN-raw.mp4) | train; nighttime moving-camera pedestrian street | 960×540 / 30 / 654 / 21.8 s | [MOT17-10-FRCNN-browser-h264.mp4](datasets/street-video/mot17/MOT17-10-FRCNN-browser-h264.mp4) |

The two raw previews use MPEG-4 Part 2 encoding and are not suitable as direct replay inputs for
the current Chrome setup. The browser uses explicitly converted H.264/MP4 copies, produced with
FFmpeg 7.1, libx264, CRF 18, yuv420p, the High profile, original PTS passthrough, and faststart.
The videos are not edited, resized, looped, overlaid, or frame-rate-adjusted. Transcoding changes
pixels, so byte-for-byte or image identity is not claimed. The offline conversion tool uses
`imageio-ffmpeg==0.6.0`, managed separately from backend and inference dependencies. The page,
launcher, and algorithm do not transcode automatically or fall back to another codec.

The source and copy retain the same dimensions, frame count, and FPS. Official source URLs,
per-file byte counts and SHA256 values, and portable transcoding parameters are recorded in
[SOURCES.json](datasets/street-video/SOURCES.json). The run tool writes per-frame decoding,
latency, and browser events to a local JSON file; these run details are not maintained with the
input videos. See the [local MVP guide](../LOCAL-MVP.md#acceptance-method-and-boundaries) for
acceptance criteria.

The [official MOT17Labels.zip](https://motchallenge.net/data/MOT17Labels.zip) must be prepared
separately and is not part of the repository video assets. Its
`train/MOT17-10-FRCNN/gt/gt.txt` contains 17,450 annotations, including 12,839 valid pedestrian
annotations and 57 track IDs across frames 1–654; public test ground truth for sequence 07 is not
included in the package. The original JPG frame set listed by the official site and `seqinfo.ini`
is 1920×1080, while the downloaded preview has been reduced to 960×540. Formal evaluation must
download the original frames, align frame numbers/timestamps and coordinates, and use an
established evaluation protocol. Current replay results must not be reported as standard MOT
scores. DPM/FRCNN/SDP are three public detector inputs for the same scene, not three independent
videos.

The two current copies use the existing `/integration/video/` local entry point and retain maximum
dimension 640, JPEG quality 80, confidence 0.25, native FP32, and existing session/in-flight
budgets. Tracking, motion state, and risk alerts can be observed for their output and lifecycle;
these assets cannot establish the accuracy of metric distance, speed, TTC, or risk judgments. If
depth ground truth is needed later, design a separate evaluation adapter using the camera
calibration and ground-truth correspondences from KITTI/Cityscapes or JRDB below.

## How Much Data Is Needed?

The small-sample sizes below are engineering suggestions, not statistical minimum guarantees.
The script does not sample or split data automatically:

| Stage | Suggested Quantity | Questions It Can Answer |
| --- | --- | --- |
| Functional check | 5–20 photos from different scenes; the bundled single image can first verify startup | Whether both models load and produce boxes, distances, and annotations, and whether failures are explicit |
| Initial comparison | A fixed set of 100–300 independent scene photos | Compare outputs, timing, and failures on the same inputs; accuracy can be compared only when ground truth is available |
| Formal detection comparison | All 5,000 images in COCO val2017 | Compare detection quality using consistent classes, official detection annotations, and an evaluation protocol |
| Formal indoor-depth comparison | The standard 654 NYU Depth V2 test images | Compare depth error using consistent depth ground truth, valid-pixel masks, and a protocol |
| Additional phone scenarios | 50–100 independent scenes with measured target depth | Examine phone cameras, distance ranges, lighting, and occlusion beyond public datasets |

Adjacent frames in continuous video, or repeating one image with `--repeat`, do not add
independent samples; the latter is only for observing repeated runs. When model differences are
small, 100 images may not produce a stable ranking. Expand to the full test set and report
uncertainty by scene. Functional tests need no labels; accuracy tests require detection
box/class ground truth and metric depth ground truth aligned with RGB.

## Public Datasets Identified

| Dataset and Official Source | Size and Download Guidance | Evaluation Scope |
| --- | --- | --- |
| [COCO](https://cocodataset.org/#download) | val2017 has 5,000 images (about 1 GB); train/val annotations are about 241 MB. See the [official COCO-Stuff download table](https://github.com/nightrome/cocostuff). | General object detection. It has no metric-depth ground truth and cannot establish distance accuracy. |
| [NYU Depth V2](https://cs.nyu.edu/~fergus/datasets/nyu_depth_v2.html) | 1,449 aligned RGB/depth pairs with class and instance annotations; the full labeled MAT package is about 2.8 GB. Start with labeled data; the roughly 428 GB raw package is not required. | Indoor depth. Original instance annotations can define target regions for object-distance evaluation with class mapping. |
| [KITTI Depth Prediction](https://www.cvlibs.net/datasets/kitti/eval_depth.php?benchmark=depth_prediction) | About 93,000 depth maps are available officially; the depth annotation package is about 14 GB and must be paired with RGB. Do not mix different benchmark/Eigen splits. | Sparse LiDAR depth in outdoor road/vehicle scenes; evaluate only valid ground-truth pixels. |
| [Cityscapes](https://www.cityscapes-dataset.com/dataset-overview/) | 5,000 finely annotated images, including 500 val images; registration is required. Download the matching RGB, instance annotations, disparity, and camera files. | Street-scene pedestrian/vehicle instances and depth comparison. Disparity is produced by a stereo algorithm and is not high-accuracy LiDAR ground truth. |

NYU is the most suitable starting point for indoor distance comparisons. In the original MAT
files, `depths` is metric depth after hole filling, while `rawDepths` is the unfilled metric depth
projected into RGB. Fix the selected field and valid-pixel mask.
[Original field documentation](https://cs.nyu.edu/~fergus/datasets/nyu_depth_v2.html) is available.
Ultralytics also provides an approximately 1.5 GB
[NYU PNG conversion package](https://github.com/ultralytics/assets/releases/download/v0.0.0/nyu-depth-png.zip):
795 train images and 654 val images (the standard Eigen test split), with RGB under `images/val`
and depth under `depth/val`. Depth PNGs store uint16 millimeters; divide by 1,000 for meters. This
convenient format is for RGB/depth pairing; retrieve object-instance annotations from the original
dataset. See the [conversion package documentation](https://docs.ultralytics.com/datasets/depth/nyu-depth-v2).

The [Ultralytics KITTI format](https://docs.ultralytics.com/datasets/depth/kitti) currently uses
652 Eigen test images with improved ground truth; divide PNG values by 256 to obtain meters. Full
automatic conversion downloads about 175 GB of RGB data and 14 GB of depth data. Official notes
state that published weights used an older training split containing 72 of these test frames, so
KITTI results from those weights cannot be claimed as fully independent tests. Record the exact
weights and split version, and add independent real-world scenes.

See the [official scripts documentation](https://github.com/mcordts/cityscapesScripts) for
Cityscapes instance classes, the 500-image val split, disparity encoding, and camera calibration.
Convert disparity using the dataset's stereo-camera calibration; the original integer values are
not meters. This conversion is only for establishing an evaluation reference. This project's
predicted distances continue to come from YOLO26 Depth, without box-size or focal-length heuristics.

## Use the Current Script After Downloading

Put large datasets in `backend/model_tests/datasets/`. Full datasets, annotations, and generated
results remain ignored by Git, except for the four test videos above, their source manifest, and
directory documentation. Missing files are not downloaded automatically. Run the following
commands from `backend/model_tests`; model weights continue to be shared from `backend/models/`:

```powershell
# Bundled example; no dataset download is required
..\.venv-inference\Scripts\python.exe -X utf8 .\run_depth.py --output outputs/bus-run-3

# Your RGB image directory: process all files recursively without sampling
..\.venv-inference\Scripts\python.exe -X utf8 .\run_depth.py --input datasets/my-photos --output outputs/photos-run-1

# RGB test directory extracted from the NYU PNG package
..\.venv-inference\Scripts\python.exe -X utf8 .\run_depth.py --input datasets/nyu-depth-png/images/val --output outputs/nyu-n-run-1

# Explicitly select another prepared, compatible YOLO26 Depth weight file
..\.venv-inference\Scripts\python.exe -X utf8 .\run_depth.py --input datasets/nyu-depth-png/images/val --depth-weights ../models/yolo26s-depth.pt --output outputs/nyu-s-run-1 --label yolo26s-depth
```

`--input` must point to RGB images or an RGB directory; do not point it to a dataset root that
also contains RGB, depth, and mask data. The script recursively reads jpg/jpeg/png/bmp/webp and
does not automatically identify which PNGs contain ground truth. The output directory must be
new. On failure the exit code is 1; a started run retains `status=failed` and partial results,
with no retry. Full public datasets are not included in the repository; prepare the required files
from their official sources before use.

The current detection loader validates the existing YOLO26n weights and manifest;
`--weights` is not a generic interface for arbitrary detection models. Select compatible YOLO26
Depth weights explicitly with `--depth-weights`. Comparing other detection architectures later
requires a separate evaluation adapter that preserves the existing production-inference contract.

## Conditions to Fix for Formal Comparisons

- Fix the test set and split, RGB/ground-truth correspondence, class mapping, input/weight SHA256,
  dependency versions, GPU, precision, and input dimensions. The current script records hashes,
  preprocessing settings, and per-frame metadata for traceability; it does not change experiment
  seeds, splits, or existing evaluation metrics.
- Current inputs are resized to a maximum dimension of 640 using the existing camera pipeline,
  then encoded as JPEG quality 80. `bbox` uses these frame coordinates. Exports record both
  `source_size` and `frame_size`; align ground truth using the same scale and do not use original
  image coordinates directly.
- The current confidence 0.25 is an inference setting for functional use. Formal COCO AP must use
  the project's existing evaluation pipeline; thresholded outputs must not be presented as
  standard full mAP.
- For depth comparisons, specify valid pixels, cropping, maximum depth, and whether scale alignment
  is applied. A future protocol should report metric-distance MAE/AbsRel/RMSE without scaling to
  ground truth; the current script does not calculate these metrics. Published metrics in the
  [Ultralytics NYU documentation](https://docs.ultralytics.com/datasets/depth/nyu-depth-v2) use TTA
  and ground-truth scale alignment, and its built-in validator also performs median alignment.
  Such scores do not directly establish the accuracy of raw output distances in meters.
- Define the same ground-truth box/instance region or fixed detection-to-ground-truth matching
  rule before measuring object distance, and report missed detections and the proportion without
  valid distance. Comparing only objects detected by each model can make a model that misses
  difficult targets appear better. NYU/Cityscapes classes also need mapping to detection classes.
- Real-world measurements must distinguish depth along the camera optical axis from slant range
  to a target; current output is optical-axis depth. When boxes include background or occlusion,
  the median may not represent the target surface; retain such samples to inspect errors.
- Current `predict_wall_ms` is the local wall-clock time for one full `predict()` call, including
  first-call Graph/predictor initialization but excluding model loading, input preprocessing, and
  file saving. All frames are retained, including the first; do not invert this duration and call
  it video FPS. Local FP32 and existing production compiled-FP16 are different runtime conditions
  and must be reported separately.

See [README.md](README.md) for installation and usage, and [DEPTH.md](../DEPTH.md) for fusion and
GPU verification. Future formal evaluation should add a dedicated script for reading ground truth
and calculating metrics, using a predefined protocol and the project's existing evaluation
configuration.
