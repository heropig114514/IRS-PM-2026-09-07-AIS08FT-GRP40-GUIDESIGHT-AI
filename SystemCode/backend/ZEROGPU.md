# Current ZeroGPU Video Path

The phone entry is https://47.239.50.129/prs/live/; processing modes are Echo and Hugging Face ZeroGPU only. The original `/prs/` route now serves this page. CPU, single-frame HF, segmented-video, frontend-box-drawing, and legacy 20-second session modes have been removed.

HF retains only the `detect_live` allocation API and the `/prs_live/ws` binary stream. The browser connects to PRS over same-origin `/ws/detect/hf/`; PRS connects to HF using server-private credentials. The first frame runs alone, followed by a default 12 FPS sampling cap and at most five in-flight jobs. Results are validated and displayed in order as complete annotated JPEGs. One GPU allocation lasts at most 55 seconds and is released on explicit stop, disconnect, timeout, or idle input. The user starts again manually; the client does not request another allocation automatically.

Before startup, both free GPU seconds must be at least 90 and free call count must be greater than zero; the request is rejected if either is insufficient or cannot be confirmed. This project uses only ZeroGPU's daily free quota and does not request dedicated or paid hardware. Inference conditions remain the original YOLO26n/640/confidence 0.25/JPEG quality 0.8. Actual compute precision and backend are declared by the required `models/inference-plan.json`. Three separate processes from the same notebook version must each complete COCO validation on 5,000 images; every AP reduction must be at most 0.5 percentage points. Public result arrays remain FP32.

On 2026-10-05, v8's repeated confirmation selected FP16/fusion/channels-last/default compilation/Graph for the pure-inference objective. HF commit `eb063ebc` contains cache reuse and same-PID frontend-state reset. Complete COCO evidence consists of three 5,000-image T4 processes. v11/v12 are cache-implementation diagnostics; HF ran only two short 8-frame calls. Historical AOT and public long-run measurements are retained, but public FPS was not used to choose the inference method. See [PHONE-LIVE.md](PHONE-LIVE.md) for current deployment and verification records.

For development, `HF_INFERENCE_TOKEN` is stored in the private `SystemCode/backend/.env`; deployment uses write-permission `HF_TOKEN` in private `SystemCode/backend/.env.hf`. Both files are excluded from Git, and server-private configuration is mode 0600. The browser never receives a token. SSH details written at runtime to `server_info.txt` are not included in source, logs, or the public Space.

`python -m tools.deploy_space` creates a source allowlist for the current path. Explicit `--publish` combines source updates and old-file removal in one HF commit with parent-commit validation. Deployment does not change hardware. The selected compilation strategy is separately compiled on the actual HF GPU at startup. Cached JIT retains official artifacts and Inductor/Triton directories. Every allocation resets frontend state (HF may reuse the same PID), strictly validates cache/hardware/runtime/configuration, requires an FX cache hit, and captures the current CUDA Graph. T4 binaries are not directly migrated, and failures do not trigger backend switching or implicit recompilation.

Public detection results, tail-latency limits, and test scope are in [PHONE-LIVE.md](PHONE-LIVE.md).
